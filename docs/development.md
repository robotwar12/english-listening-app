# 개발·수정·검증 절차

## 실행

`package-lock.json`에 맞춰 npm을 사용한다. 새 환경에서는 `npm ci`로 설치한다. 이미 의존성이 준비된 환경에서 매번 재설치할 필요는 없다.

```sh
npm run dev
```

기본 주소는 `http://localhost:3000`이다. 포트가 사용 중이면 터미널에 출력된 실제 주소를 확인한다.

```sh
npm run build
npm run start
```

프로덕션 실행은 빌드 성공 후 진행한다. `next/font/google` 빌드는 글꼴 다운로드에 네트워크가 필요할 수 있다. PWA 파일도 생성되므로 전후 Git diff를 확인한다.

## 기능 수정 순서

1. 요청의 현재 동작과 기대 동작을 확인하고 `git status --short`로 기존 변경을 파악한다.
2. [코드 지도](code-map.md)에서 관련 기능을 찾고 심볼 검색으로 필요한 코드만 읽는다.
3. 상태·호출부·데이터 계약에 영향을 주는 범위를 확인한 뒤 수정한다.
4. 아래 표에 따라 필요한 검사와 사용자 동작을 검증한다.
5. 변경된 경로·동작·명령만 문서에 반영하고 `git diff --check` 및 최종 diff를 확인한다.
6. 변경 내용, 검증 결과, 실행하지 못한 검증을 보고한다.

검색 예시 (`rg`가 없는 환경에서도 사용 가능):

```sh
git grep -n -E 'togglePlay|nextTrack|handleEnded' -- src
git ls-files src
sed -n '150,220p' src/components/english-listening-app.tsx
```

줄 범위는 예시다. 실제 위치는 검색 결과를 기준으로 한다. 미추적 파일은 `git ls-files`에 나타나지 않으므로 필요하면 `find src -type f`를 사용한다.

## 변경 종류별 검증

| 변경 | 검증 |
|---|---|
| 문서만 변경 | 링크·경로·사실 확인, `git diff --check`; 앱 빌드 불필요 |
| TS/TSX 변경 | `npx tsc --noEmit --incremental false`, `npx eslint src` |
| 학습 UI·오디오 | 정적 검사 + 관련 수동 시나리오, 모바일·데스크톱 화면 |
| 데이터·API | JSON 파싱, 파일명/번호/뜻 키 일치, API 응답·정렬·오디오 URL |
| 의존성·라우팅·설정 | 관련 설정 검사, `npm run build`, 영향받는 사용자 흐름 |
| PWA | manifest 파싱, 프로덕션 빌드·실행, 서비스 워커·설치·캐시 |

현재 `test` 스크립트나 별도 자동 테스트 스위트는 없다. 정적 검사 통과와 브라우저 동작 검증은 구분해서 보고한다. 로직이 복잡해질 때는 의미 있는 동작 테스트를 추가한다.

## 학습 기능 수동 시나리오

- 첫 로딩: 오디오와 뜻이 로드되고 랜덤 생성이 활성화되는지 확인한다.
- 범위 1~3: 해당 세 항목이 중복 없이 생성되는지 확인한다. 셔플 결과는 이전과 같을 수도 있다.
- 단일 번호, 빈 입력, 0, 상한 초과, 시작 > 끝을 확인한다. 현재 입력은 `parseInt`를 사용하므로 소수 엄격 검증은 구현되어 있지 않다.
- 재생·일시정지·다시 재생, 다음 곡, 다른 항목 선택, 현재 항목 재선택, 마지막 곡 버튼 비활성화를 확인한다.
- 곡 종료 시 정지하고 자동 이동하지 않는지 확인한다. 동작 변경 요청이면 새 기대 동작을 기준으로 한다.
- 뜻 숨김이 현재 단어와 목록 모두에 적용되는지, grid/list 전환과 초기화가 정상인지 확인한다.
- 시험 모드를 생성 전에 켜고 1~3 범위를 생성한다. 현재 단어와 카드/리스트에서 단어·뜻·원래 번호·파일명 대신 문제 번호만 보이는지 확인한다.
- 숨김 상태에서 재생·다음 문제·목록 선택·재생성·초기화를 확인한다. 모드를 끄면 정답과 기존 뜻 표시 설정이 복원되는지 확인한다.
- 로딩 실패나 오디오 오류를 다루는 작업이면 해당 실패 경로도 확인한다.

## PWA 검증

- 개발 모드에서는 PWA가 비활성화된다. 프로덕션 서버에서 manifest와 서비스 워커를 확인한다.
- 브라우저별 설치 지원 및 이미 설치된 상태에 따라 설치 버튼이 없을 수 있다.
- 캐시 변경은 기존 설치/서비스 워커가 있는 상태와 깨끗한 상태를 구분한다. 오래된 캐시 문제와 현재 소스 문제를 혼동하지 않는다.
- 오프라인 기능은 실제 페이지·API·음원 요청을 테스트한 범위만 보고한다.

## 분석 당시 확인 결과와 기존 문제

2026-09-16 소스·정적 검사 기준. 향후 변경 시 해당 항목을 갱신한다.

| 항목 | 결과 |
|---|---|
| `npx tsc --noEmit --incremental false` | 통과 |
| `npx eslint src` | 통과 |
| `npm run lint` | 통과. `next lint` 폐기 예정 경고 발생; 향후 Next.js 업그레이드 시 스크립트 검토 |
| 현재 audio3 / voca3200 데이터 | MP3 750개, 뜻 750개, 파일명으로 조회한 뜻 누락 0개 |
| `public/manifest.json` | description 뒤 중복 쉼표로 JSON 파싱 실패. PWA 작업 시 우선 수정·재검증 필요 |
| 시험 모드 브라우저 검증 | 개발 서버에서 숨김/복원, 카드/리스트, 재생·다음·선택, 재생성·초기화, 뜻 설정 보존 확인. 390px 모바일 화면 가로 넘침 없음 |
| 음원 재생 | 브라우저에서 paused=false, currentTime 증가, error=null 확인. 실제 스피커 청취는 미검증 |
| 기존 브라우저 경고 | layout의 metadata에 있는 themeColor/viewport를 별도 viewport export로 이동하라는 경고 |
| 프로덕션 빌드 | `npm run build` 통과 (시험 모드 배포 준비 과정에서 확인) |
| PWA 설치 | 미검증. 기존 manifest JSON 오류는 별도 수정 필요 |

manifest 오류는 기존 문제로 확인했으며 이번 문서화에서는 수정하지 않았다. 이전 데이터가 미사용이라는 이유만으로 제거하지 않는다.
